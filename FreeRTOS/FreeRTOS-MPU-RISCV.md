# FreeRTOS-MPU-RISCV

_this is still a stub_

To invoke FreeRTOS system calls from a User mode (U-mode) RISC-V assembly task, you must use the FreeRTOS-MPU RISC-V port (which uses RISC-V Physical Memory Protection, or PMP, to isolate U-mode tasks) and pass the system call index in t0 (or call the MPU_* C wrappers) before executing ecall. [1] (https://www.freertos.org/Security/04-FreeRTOS-MPU-memory-protection-unit), [2] (https://github.com/sifive/FreeRTOS-metal/blob/master/FreeRTOS-Kernel/portable/GCC/RISC-V/port.c)

## How the FreeRTOS-MPU RISC-V ecall ABI Works

When a U-mode task executes ecall, the CPU traps to M-mode with mcause = 8 (Environment call from U-mode). In the FreeRTOS-MPU RISC-V port (portable/GCC/RISC-V/ with portUSING_MPU_WRAPPERS == 1): [1] (https://www.youtube.com/watch?v=hfqBurzg6GE&t=463)

• System Call Number (t0): Unlike Linux (which uses a7), the FreeRTOS-MPU RISC-V port passes the system call index in register t0 (x5). [1] (https://github.com/sifive/FreeRTOS-metal/blob/master/FreeRTOS-Kernel/portable/GCC/RISC-V/port.c)

• Arguments (a0–a5): Up to 6 function arguments follow standard RISC-V calling convention in a0 through a5. [1] (https://medium.com/@jadhavdhananjay570/deconstructing-the-ecall-from-c-user-space-to-risc-v-bare-metal-b6586aa593ee)

• Return Value (a0): When the kernel finishes executing the wrapped API on its separate privileged syscall stack and returns via mret to U-mode, the return value is placed in a0. [1] (https://www.freertos.org/Security/04-FreeRTOS-MPU-memory-protection-unit)

• PMP Memory Isolation: A U-mode task can only read/write its own stack and up to 3 explicitly granted PMP regions. Accessing UART MMIO (0x10000000) or kernel .bss/.data directly from U-mode triggers a Store/Load Access Fault (mcause = 5 or 7) unless that memory range is mapped into one of the task's PMP regions. [1] (https://medium.com/embedworld/task-isolation-in-freertos-using-the-mpu-enabled-cortex-m-port-a4438d9a9cc5), [2] (https://www.freertos.org/Security/04-FreeRTOS-MPU-memory-protection-unit), [3] (https://www.freertos.org/Security/02-Kernel-threat-model)

## Enable the FreeRTOS-MPU RISC-V Port in Your Build

The standard RISC-V_RV32_QEMU_VIRT_GCC demo disables MPU wrappers by default. To switch it to U-mode MPU support:

### Include MPU Wrapper Sources in build/gcc/Makefile:
	• Compile FreeRTOS/Source/portable/Common/mpu_wrappers.c and mpu_wrappers_v2.c (depending on configUSE_MPU_WRAPPERS_V1).
	• Ensure the port directory includes the MPU-enabled RISC-V port (portable/GCC/RISC-V with portUSING_MPU_WRAPPERS enabled, or portable/GCC/RISC-V-MPU depending on your FreeRTOS checkout). [1] (https://www.freertos.org/Security/04-FreeRTOS-MPU-memory-protection-unit), [2] (https://forums.freertos.org/t/implementation-discuss-in-mpu-wrappers-v2-c/22675)

### Update FreeRTOSConfig.h:c
```
#define configENABLE_MPU                        1
#define configUSE_MPU_WRAPPERS_V1               0   /* Use v2 wrappers (FreeRTOS 10.6+) */
#define configTOTAL_MPU_REGIONS                 8   /* QEMU virt supports 16 PMP entries */
#define configSYSTEM_CALL_STACK_SIZE            512
```
Use code with caution.

### Update the Linker Script (fake_rom.ld):

• FreeRTOS-MPU requires aligned linker sections (__privileged_functions_start__, __privileged_functions_end__, __privileged_data_start__, __privileged_data_end__, __syscalls_flash_start__, __syscalls_flash_end__, and __unprivileged_flash_end__) so PMP hardware registers can enforce power-of-two/NAPOT boundaries. [1] (https://forums.freertos.org/t/error-with-mpu-wrappers-v2-c/20938), [2] (https://github.com/sifive/FreeRTOS-metal/blob/master/FreeRTOS-Kernel/portable/GCC/RISC-V/port.c)

### Writing the U-Mode RISC-V Assembly Task

You can invoke FreeRTOS syscalls from your .S file in two ways:

• Method A (Recommended): Call the MPU_* syscall stubs (e.g., MPU_vTaskDelay, MPU_xQueueGenericSend), which automatically load the exact syscall index into t0 and execute ecall.

• Method B (Direct ecall): Load the SYSTEM_CALL_* macro index (defined in include/mpu_syscall_numbers.h) directly into t0 and execute ecall. [1] (https://forums.freertos.org/t/putting-tasks-to-waiting-lists-from-interrupt-handlers-experiments-using-syscalls-instead-of-freertos-task-api-functions-in-order-to-access-queues/25003)

```
Example: umode_task.S

asm
#include "mpu_syscall_numbers.h"

.section .text
.align 4
.global vUserModeAsmTask
.type vUserModeAsmTask, @function

/* External MPU syscall stubs (generated by mpu_wrappers_v2) */
.extern MPU_vTaskDelay
.extern MPU_xTaskGetTickCount

vUserModeAsmTask:
    /* NOTE: Do NOT touch M-mode CSRs (mstatus, mtvec, pmpcfg0) here!
     * This task runs in U-mode; reading/writing M-mode CSRs will trap
     * with an Illegal Instruction exception (mcause = 2). */

    li      s0, 0                   /* U-mode loop counter in s0 */

umode_loop:
    /* 1. Direct ecall: xTaskGetTickCount()
     * Load syscall number into t0 and trap to M-mode via ecall */
    li      t0, SYSTEM_CALL_xTaskGetTickCount
    ecall                           /* Returns current tick count in a0 */
    mv      s1, a0                  /* Save tick count in s1 */

    /* 2. Direct ecall: vTaskDelay(500)
     * Put argument (500 ticks) in a0, syscall index in t0, and execute ecall */
    li      a0, 500
    li      t0, SYSTEM_CALL_vTaskDelay
    ecall

    /* 3. Equivalent call via C MPU wrapper stub (also executes ecall internally) */
    li      a0, 250
    jal     ra, MPU_vTaskDelay

    addi    s0, s0, 1
    j       umode_loop
```
Use code with caution.

### Creating the U-Mode Task in C (xTaskCreateRestricted)

Normal xTaskCreate() creates privileged M-mode tasks. To launch vUserModeAsmTask in User mode (U-mode) with its own PMP regions, create it using xTaskCreateRestricted() (omitting portPRIVILEGE_BIT from uxPriority): [1] (https://www.freertos.org/media/2025/FreeRTOS_Reference_Manual_V8.2.1.pdf), [2] (https://www.freertos.org/Security/04-FreeRTOS-MPU-memory-protection-unit)
c
```
extern void vUserModeAsmTask( void * pvParameters );

/* Task stack must be aligned to power-of-two size for RISC-V PMP NAPOT rules */
static StackType_t xUserTaskStack[ 512 ] __attribute__( ( aligned( 512 * sizeof( StackType_t ) ) ) );

/* Optional: grant U-mode read/write access to QEMU NS16550 UART (0x10000000) */
static const TaskParameters_t xUserTaskParams =
{
    .pvTaskCode     = vUserModeAsmTask,
    .pcName         = "UAsmTask",
    .usStackDepth   = 512,
    .pvParameters   = NULL,
    .uxPriority     = tskIDLE_PRIORITY + 1, /* No portPRIVILEGE_BIT -> runs in U-mode */
    .puxStackBuffer = xUserTaskStack,
    .xRegions       =
    {
        /* Base Address, Length (power of 2), Permissions */
        { ( void * ) 0x10000000, 0x1000, tskMPU_REGION_READ_WRITE | tskMPU_REGION_EXECUTE_NEVER },
        { 0, 0, 0 },
        { 0, 0, 0 }
    }
};

void vStartUserAsmDemo( void )
{
    xTaskCreateRestricted( &xUserTaskParams, NULL );
}
```
Use code with caution.

(Tip: If you grant the 0x10000000 UART region in xRegions above, your U-mode assembly task can also write characters directly to QEMU's serial console via sb t1, 0(t2) without faulting!)

### Running and Verifying U-Mode Execution in QEMU

Launch QEMU with PMP enabled (virt enables 16 PMP regions by default):

```
$ bash \
qemu-system-riscv32 \
  -nographic \
  -machine virt \
  -net none \
  -bios none \
  -smp 1 \
  -kernel ./build/gcc/output/RTOSDemo.elf
```
Use code with caution.

(Note: Keep -smp 1 when enabling FreeRTOS-MPU, as FreeRTOS-MPU does not support SMP multicore configurations.)

### Confirm in GDB 

To confirm in GDB that your assembly task is truly running in U-mode:

1. Break at umode_loop in GDB (break umode_loop, continue).

2. Inspect mstatus (info registers mstatus): bits [12:11] (MPP) were 00 (User mode) when mret jumped into vUserModeAsmTask, and attempting csrr a0, mstatus inside umode_loop will immediately jump to freertos_risc_v_exception_handler with mcause = 2.

## Linker script 

To run the FreeRTOS-MPU RISC-V port in QEMU virt, your linker script (fake_rom.ld) must group privileged kernel code, system call entry wrappers, unprivileged code, and privileged kernel data into power-of-two aligned regions (required by RISC-V PMP NAPOT addressing).

Complete MPU-Compatible fake_rom.ld for QEMU virt

Replace FreeRTOS/FreeRTOS/Demo/RISC-V_RV32_QEMU_VIRT_GCC/build/gcc/fake_rom.ld with the following linker script:

```
ld

OUTPUT_ARCH( "riscv" )
ENTRY( _start )

/* QEMU virt machine RAM starts at 0x80000000.
 * Reserve 16 KB for privileged kernel code, 4 KB for syscall wrappers,
 * and 16 KB for privileged kernel data—all power-of-two aligned for PMP NAPOT. */
__PRIVILEGED_FLASH_SIZE__ = 0x4000;   /* 16 KB */
__SYSCALLS_FLASH_SIZE__   = 0x1000;   /*  4 KB */
__PRIVILEGED_DATA_SIZE__  = 0x4000;   /* 16 KB */

MEMORY
{
    /* Total RAM: 1 MB starting at 0x80000000 */
    RAM (rwx) : ORIGIN = 0x80000000, LENGTH = 1024K
}

SECTIONS
{
    /* =====================================================================
     * 1. PRIVILEGED FUNCTIONS (M-mode only; U-mode cannot read/execute)
     * ===================================================================== */
    .privileged_functions : ALIGN( __PRIVILEGED_FLASH_SIZE__ )
    {
        __privileged_functions_start__ = .;
        *(.text.init)
        *(privileged_functions)
        *(privileged_functions.*)
        . = ALIGN( __PRIVILEGED_FLASH_SIZE__ );
        __privileged_functions_end__ = .;
    } > RAM

    /* =====================================================================
     * 2. SYSTEM CALL WRAPPERS (Executable by U-mode to trigger ecall)
     * ===================================================================== */
    .freertos_system_calls : ALIGN( __SYSCALLS_FLASH_SIZE__ )
    {
        __syscalls_flash_start__ = .;
        *(freertos_system_calls)
        *(freertos_system_calls.*)
        . = ALIGN( __SYSCALLS_FLASH_SIZE__ );
        __syscalls_flash_end__ = .;
    } > RAM

    /* =====================================================================
     * 3. UNPRIVILEGED CODE & READ-ONLY DATA (Executable/Readable by U-mode)
     * ===================================================================== */
    .text :
    {
        __unprivileged_flash_start__ = .;
        *(.text.unlikely .text.unlikely.*)
        *(.text.startup .text.startup.*)
        *(.text .text.*)
        *(.gnu.linkonce.t.*)
    } > RAM

    .rodata :
    {
        *(.rodata .rodata.*)
        *(.gnu.linkonce.r.*)
        *(.srodata .srodata.*)
        /* Align end of unprivileged flash to a power of 2 (e.g., 64 KB) for PMP */
        . = ALIGN( 0x10000 );
        __unprivileged_flash_end__ = .;
    } > RAM

    /* =====================================================================
     * 4. PRIVILEGED KERNEL DATA (M-mode only; isolated from U-mode)
     * ===================================================================== */
    .privileged_data : ALIGN( __PRIVILEGED_DATA_SIZE__ )
    {
        __privileged_data_start__ = .;
        *(privileged_data)
        *(privileged_data.*)
        . = ALIGN( __PRIVILEGED_DATA_SIZE__ );
        __privileged_data_end__ = .;
    } > RAM

    /* =====================================================================
     * 5. UNPRIVILEGED / SHARED DATA, BSS, & BOOT STACK
     * ===================================================================== */
    .data : ALIGN( 16 )
    {
        __data_start__ = .;
        *(.data .data.*)
        *(.gnu.linkonce.d.*)
        . = ALIGN( 8 );
        PROVIDE( __global_pointer$ = . + 0x800 );
        *(.sdata .sdata.* .sdata2.*)
        *(.gnu.linkonce.s.*)
        . = ALIGN( 16 );
        __data_end__ = .;
    } > RAM

    .bss (NOLOAD) : ALIGN( 16 )
    {
        __bss_start__ = .;
        *(.sbss .sbss.*)
        *(.gnu.linkonce.sb.*)
        *(.bss .bss.*)
        *(.gnu.linkonce.b.*)
        *(COMMON)
        . = ALIGN( 16 );
        __bss_end__ = .;
    } > RAM

    /* Stack used during boot (start.S) and by M-mode interrupts/traps */
    .stack (NOLOAD) : ALIGN( 16 )
    {
        __stack_bottom__ = .;
        . += 0x1000; /* 4 KB ISR / boot stack */
        __stack_top__ = .;
        PROVIDE( _sp = __stack_top__ );
    } > RAM

    _end = .;
}
```
Use code with caution.

### Key PMP Rules to Watch For

• NAPOT Alignment Rule: RISC-V PMP NAPOT (Naturally Aligned Power-Of-Two) requires every protected region's start address to be a multiple of its size (for example, a 0x4000 byte region must start at an address ending in 0x0000, 0x4000, 0x8000, or 0xC000). The ALIGN(...) directives in the script above enforce this automatically.

• Overflow Check: If your kernel code grows larger than 16 KB (0x4000) or unprivileged code + .rodata exceeds 64 KB (0x10000), increase __PRIVILEGED_FLASH_SIZE__ or . = ALIGN( 0x10000 ) to the next power of two (0x8000, 0x20000, etc.) so __privileged_functions_end__ - __privileged_functions_start__ remains an exact power of two.

• Task Stacks: Every U-mode task stack passed to xTaskCreateRestricted() must also obey NAPOT—allocate it as a power-of-two byte size (e.g., 2048 bytes = 512 * sizeof(StackType_t)) with __attribute__((aligned(2048))).
